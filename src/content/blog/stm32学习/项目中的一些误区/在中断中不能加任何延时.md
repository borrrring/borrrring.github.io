## 为什么即使用于消抖也不行？

按键消抖通常需要 **10-30ms 的延时**。在 ISR 里做这件事：

```
  CPU 正在跑一个任务（比如充电控制）
      ↓
  按键按下 → EXTI 中断触发
      ↓
  CPU 跳进 ISR
      ↓
  ISR 里 delay(20ms) —— 这 20ms 里：
    ├── 充电任务被冻结（本来正在算电流）
    ├── ADC 采样被延迟（本来每秒要采 1000 次）
    ├── DS18B20 温度读取被延迟（有超时窗口）
    └── 系统整体"冻结"了 20ms
      ↓
  ISR 结束，回去继续任务
```

在 72MHz 的 STM32F103 上，**20ms ≈ 1,440,000 个 CPU 周期**。这期间：

- 你的 ADC 可能少采了 20-40 个点
- 充电 PWM 控制环可能跑了没更新
- 如果另一个更高优先级的中断发生了（比如保护中断），它虽然能打断这个 ISR，但回来后消抖还在继续浪费 CPU

## 正确的按键消抖方案

**方案一：在任务里消抖（推荐，TCS 项目最合适）**

```c
// 外部中断里只发信号量
void EXTI0_IRQHandler(void) {
    BaseType_t xHigherPriorityTaskWoken = pdFALSE;
    
    if (EXTI_GetITStatus(EXTI_Line0) != RESET) {
        xSemaphoreGiveFromISR(xButtonSemaphore, &xHigherPriorityTaskWoken);
        EXTI_ClearITPendingBit(EXTI_Line0);
    }
    
    portYIELD_FROM_ISR(xHigherPriorityTaskWoken);
}

// 单独的任务里做消抖
void vButtonTask(void *pvParameters) {
    for (;;) {
        // 等中断通知
        xSemaphoreTake(xButtonSemaphore, portMAX_DELAY);
        
        // 延时 20ms 消抖（这是在任务里，完全OK！）
        vTaskDelay(pdMS_TO_TICKS(20));
        
        // 再读一次确认电平
        if (GPIO_ReadInputDataBit(GPIOA, GPIO_Pin_0) == RESET) {
            // 确认是有效按键
            xSemaphoreGive(xKeyPressSemaphore);
        }
    }
}
```

**方案二：只用硬件消抖（最简单，零代码开销）**

给按键并联一个 **0.1μF 电容** + 串联 10KΩ 电阻，RC 滤波电路 ≈ 1ms 时间常数，硬件上就把抖动滤掉了。然后中断里直接读电平判断，**不需要任何软件延时**。

```c
// 小技巧：STM32 的输入滤波器也能硬件消抖
GPIO_InitStructure.GPIO_Filter = GPIO_Filter_8;  // 8个采样周期去抖
// 但 F103 的 GPIO 没有这个功能，所以用 RC 电路
```

**方案三：定时器轮询（不依赖中断）**

```c
// 在 ADC 任务或者单独的 1ms 定时任务里
void vKeyScanTask(void *pvParameters) {
    static uint8_t key_debounce_cnt = 0;
    static uint8_t key_last_state = 1;  // 默认高电平（上拉）
    
    for (;;) {
        uint8_t key_now = GPIO_ReadInputDataBit(GPIOA, GPIO_Pin_0);
        
        if (key_now == key_last_state) {
            key_debounce_cnt = 0;  // 电平没变，重置计数
        } else {
            key_debounce_cnt++;
            if (key_debounce_cnt >= 20) {  // 20ms 连续稳定
                key_last_state = key_now;
                if (key_now == 0) {
                    // 确认按键按下
                    xSemaphoreGive(xKeyPressSemaphore);
                }
                key_debounce_cnt = 0;
            }
        }
        
        vTaskDelay(pdMS_TO_TICKS(1));  // 每 1ms 查一次
    }
}
```

**方案三的优点**：不占用中断、不阻塞任何任务、消抖时间精确可调，在 TCS 这种需要同时管理充电 + ADC + 温度的项目里最推荐。

## 如果真的要在中断里做延时怎么办？

只有一个合法情况：配合定时器做**状态机消抖**，依然不会阻塞 ISR：

```c
// 用 TIM 定时器的输入捕获功能做硬件消抖
// STM32 的 TIM 有自带数字滤波，设置好寄存器后，
// TIM 输入引脚上的信号抖动被硬件滤掉后才触发中断
// ISR 里直接读结果，不用 delay
```

---

**总结：中断里永远不要用 `vTaskDelay` 或任何 `for(i=0;i<大数;i++)` 这种空循环延时，无论目的是消抖还是别的。把消抖逻辑放到任务里，或者用硬件滤波。**
